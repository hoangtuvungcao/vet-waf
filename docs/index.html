One engine, the whole frontend

Vet-WAF fuses a web accelerator and a multi-layer firewall into a single kernel-space core — no context switches, no user-space copy overhead.

🛡️

Web Application Firewall

Inspect and filter HTTP/HTTPS at wire speed. Block injections, bad bots, and abusive clients with rule-based and rate-limiting policies (Frang).

⚡

HTTPS Load Balancer

Terminate TLS and balance traffic across upstreams with hash, ratio, and predictive schedulers — all inside the kernel data path.

🚀

Web Accelerator

A built-in, RAM-resident HTTP cache serves hot content in microseconds and shields origins from load spikes.

🌊

DDoS Mitigation

Absorb volumetric and application-layer floods early in the stack, with seamless integration into Linux iptables / nftables.

🔐

Kernel-native TLS

Vet-WAF TLS runs the handshake in-kernel — 40–80% faster than Nginx/OpenSSL, with optional constant-time crypto.

📊

Observability

Structured access logging to ClickHouse, live perfstat via procfs, and APM-grade latency percentiles out of the box.

How it works

Vet-WAF is a set of loosely-coupled Linux kernel modules that sit between the NIC and your origin servers.

Clients
HTTP/1.1 · HTTP/2 · TLS
→
Vet-WAF core
WAF · LB · Cache · TLS · DDoS — in kernel
→
Upstreams
your app / origin servers
tempesta_fw tempesta_tls tempesta_db tempesta_lib tempesta_regex

Module names keep the upstream kernel-ABI identifiers for binary compatibility with the patched Linux image.

Quick start

Build from source against a Vet-WAF-patched Linux 6.12.12 kernel, then start the service.

bash 
# 1. Clone
git clone https://github.com/hoangtuvungcao/vet-waf.git
cd vet-waf

# 2. Build the kernel modules and user-space tools
make

# 3. Load and start Vet-WAF (reads /etc/vet_waf/vet_waf.conf)
sudo ./scripts/vet_waf.sh --start

# 4. Check runtime state
cat /proc/vet_waf/perfstat
sudo sysctl net.vet_waf.state

A minimal config lives in etc/vet_waf.conf. The systemd unit is vet-waf.service.
