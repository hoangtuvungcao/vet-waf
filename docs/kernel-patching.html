Kernel

Kernel patching

Vet-WAF lives in the TCP/IP stack, so it needs kernel hooks the stock tree does not export. This is a one-time patch, build, and reboot.

Why a patched kernel

Vet-WAF is not a user-space proxy. It runs inside the Linux TCP/IP stack, which lets it answer a request without ever copying data to user space or scheduling a process. That is where the throughput comes from — and it is why the stock kernel is not enough.

The patch exports hooks the stock kernel keeps private: socket-level callbacks for zero-copy reads, TLS handshake interception, and the ability to send a response straight from the softirq that received the packet.

Patching replaces the kernel your machine boots. Always keep the previous kernel entry in your bootloader so you can recover if the new one fails to boot.

Apply the patch

Vet-WAF targets Linux 6.12.12 exactly. The patch is linux-6.12.12.patch in the repository root. Other point releases may apply with offsets, but only 6.12.12 is tested.

bash 
# 1. Fetch the exact upstream source
curl -O https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.12.12.tar.xz
tar xf linux-6.12.12.tar.xz
cd linux-6.12.12

# 2. Dry-run first — this changes nothing and reports conflicts
patch -p1 --dry-run < ../vet-waf/linux-6.12.12.patch

# 3. If the dry run is clean, apply for real
patch -p1 < ../vet-waf/linux-6.12.12.patch

Never skip the --dry-run. If it reports a single Hunk FAILED, stop: a partially patched tree builds a kernel that loads Vet-WAF and then misbehaves in ways that are very hard to debug.

Configure and build

Start from your running configuration so hardware support is preserved, then enable the options Vet-WAF needs.

bash 
# Inherit the running kernel's config
cp /boot/config-$(uname -r) .config
make olddefconfig

# Required by Vet-WAF
scripts/config --enable SECURITY
scripts/config --enable NETFILTER
scripts/config --enable  TLS
scripts/config --disable DEBUG_INFO_BTF   # cuts build time sharply

# Build (adjust -j to your core count) and install
make -j"$(nproc)"
sudo make modules_install install
sudo reboot

After the reboot, confirm you are on the patched kernel before building Vet-WAF itself:

bash 
uname -r      # expects: 6.12.12

If the new kernel will not boot

  1. At the bootloader menu, choose Advanced options and boot the previous kernel. Nothing is lost — the old kernel is still installed.
  2. Once booted, read the failure: journalctl -k -b -1 shows the kernel log from the failed boot attempt.
  3. Most failures are a missing storage or filesystem driver in the initramfs. Rebuild it: sudo update-initramfs -c -k 6.12.12.
  4. To remove the patched kernel entirely: sudo rm -rf /boot/*6.12.12* /lib/modules/6.12.12 then sudo update-grub.
